# 🎯 游戏设计思路

## 1. 架构总览

```
MainEntry.cs (入口)
    ↓
MainController.cs (总控制器)
    ↓
GameController.cs (游戏控制器)
    ↓
各功能模块 (消除系统、关卡系统、UI系统...)
```

## 2. 入口机制

### MainEntry.cs
- **职责**: 所有控制器的总入口
- **设计**: 通过 static 属性方式获取其他组件
- **特点**: 集中管理，避免循环引用

### MainController.cs
- **职责**: 总控制器，单例模式
- **持有**: GameController 实例
- **包含**: 所有功能模块的引用和协调

### GameController.cs
- **职责**: 游戏核心控制器
- **核心**: 游戏状态机管理
- **状态分类**:
  - 初始化状态
  - 准备状态
  - 进行中状态
  - 结算状态

## 3. 核心模块职责

### 3.1 MatchCore (消除核心)
- **元素网格管理**: 二维数组维护棋盘状态
- **匹配检测**: 横向、纵向、三连及以上检测
- **消除逻辑**: 元素消除、掉落、填充
- **元素生成**: 随机/指定类型元素生成

### 3.2 SkillSystem (技能系统)
- **技能配置**: JSON配置文件管理
- **触发条件**: 消除触发、生成触发、回合结束触发
- **优先级管理**: 多技能时的执行顺序
- **效果实现**: 技能效果的代码实现

### 3.3 UISystem (UI系统)
- **窗口堆栈**: Push/Pop管理窗口显示层级
- **生命周期**: Load → Create → Refresh → Destroy
- **层级管理**: Background → Common → PopUp → Top
- **异步加载**: UniTask支持非阻塞加载

## 4. 数据流设计

```
用户输入 → GameController → MatchCore → 技能系统 → UI反馈
                  ↓
           PlayerData (持久化)
                  ↓
           Server (同步)
```

## 5. 扩展性设计

### 模块化
- 每个系统独立，通过接口通信
- 易于新增功能模块
- 降低耦合度

### 热更新
- HybridCLR支持代码热更新
- YooAsset支持资源热更新
- Luban支持配置热更新

## 6. 开发规范

### 命名规范
- Controller: 控制类，处理流程
- System: 系统类，管理功能
- Config: 配置类，数据定义
- Data: 数据类，状态存储

### 代码组织
- HotFix/: 热更新代码
- Runtime/: 运行时代码
- Editor/: 编辑器工具
